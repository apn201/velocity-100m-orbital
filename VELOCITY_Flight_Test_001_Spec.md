## 0. What changed from v1

v1 was six objects, each faster than the last. Projectile, Saturn V, Pioneer 10, asteroid, planet, galaxy. A good-looking montage that judges have seen before, and a speed ladder that only works if you quietly swap reference frames between rungs.

v2 makes the frame swap the film.

There is one test article: a 9x19 mm projectile, fired once, filmed in slow motion. It never accelerates. Nothing touches it. The instrument changes its reference frame five times and the measured speed climbs from 0.305 km/s to about 370 km/s. Roughly 1,200 times faster, without anything happening to the bullet.

Saturn V and Pioneer 10 stay, as comparison passes. In the Earth-centred frame Saturn V overtakes the bullet. In the Sun-centred frame the bullet overtakes Pioneer 10. The asteroid field is cut. The planet becomes Earth, which the bullet is riding anyway.

The ending cuts back to the opening shot. Same bullet, same slow motion, 0.305 km/s. Then:

```
MOTION DETECTED.
REFERENCE FRAME: LOCAL.
```

In v1 that line was decoration. In v2 it is the punchline.

Logline: One bullet. Five reference frames. It gets 1,200 times faster without anything touching it.

## 2. Storyboard

24 s, 576 frames. All timings come from `data/timeline.json`, not code.

### Segment 0 - Boot (0.0-1.5 s, frames 1-36)

- Black. A faint grid fades in, then the crosshair and coordinate ticks draw on.
- The title flickers on briefly: `VELOCITY // FLIGHT TEST 001`.
- The ladder appears on the right with no readings yet.

### Segment 1 - GROUND (1.5-6.0 s, frames 37-144)

- Macro shot of the projectile, side on, in extreme slow motion. The camera is locked to it, so it never moves on screen.
- The test-range grid and distance ticks stream past it from right to left. That streaming is the motion cue.
- HUD:
  - `9x19 mm PROJECTILE`
  - `147 gr FMJ`
  - `0.305 km/s`
  - `FRAME: GROUND / TEST RANGE 60.9 N`
- Ladder: first tick at 0.305.

### Segment 2 - EARTH-CENTRED (6.0-10.0 s, frames 145-240)

- Exponential pull-out. The range shrinks to a marker on a wireframe globe at 60.9 N.
- Frame-change event (section 4.3). The readout rolls from 0.305 to about 0.53 km/s, because Earth's rotation at that latitude adds about 0.23 km/s for a bullet fired due east.
- Saturn V crosses on a trans-lunar injection arc at about 10.8 km/s. HUD: `OVERTAKEN BY: SATURN V / ~10.8 km/s / TLI`.
- Ladder: second tick.

### Segment 3 - SUN-CENTRED (10.0-14.0 s, frames 241-336)

- The globe shrinks to a marker on Earth's orbit. The Sun is a small disc with orbit circles.
- Readout rolls to about 29.8 km/s.
- Pioneer 10 drifts outbound at about 12 km/s. The bullet's marker, riding Earth, overtakes it. HUD: `OVERTAKING: PIONEER 10 / ~12 km/s`.
- Ladder: third tick.

### Segment 4 - GALACTOCENTRIC (14.0-18.0 s, frames 337-432)

- The orbit shrinks to a point in a schematic spiral disk.
- Readout rolls to about 250 km/s.
- Ladder: fourth tick.

### Segment 5 - CMB REST FRAME (18.0-21.0 s, frames 433-504)

- The disk shrinks inside a sphere of the microwave sky. The dipole is one gradient from green to amber.
- Readout rolls to about 370 km/s.
- The ladder shows all five readings and a span label: `x1,200`.
- If audio exists, it rises here.

### Segment 6 - LOCAL (21.0-24.0 s, frames 505-576)

- Hard cut, the only one in the film, back to the exact composition of Segment 1. Same bullet, same slow motion. Silence.
- The HUD clears to one readout, `0.305 km/s`, then a beat later:
  - `MOTION DETECTED.`
  - `REFERENCE FRAME: LOCAL.`
- Cut to black at frame 576.

The film must work without sound.

## 3. The numbers

### 3.1 Principle

Two kinds of value, kept apart, as in v1:

- `physical_speed_km_s`: a sourced or computed real value, always paired with a frame and a source.
- `cinematic_*`: streak length, camera distance, timing. These only control the picture and never feed a label.

### 3.2 Epoch and geometry

The shot has a fixed, stated moment and place, because frame speeds depend on both:

- Epoch: `2026-10-31T23:59:00Z`, the contest deadline. The bullet is fired at the deadline.
- Location: 60.9 N, test range. Use the latitude only, no named site, unless the data file says otherwise.
- Direction: due east, horizontal.
- Muzzle velocity: 305 m/s, provisional. Verify against the Federal American Eagle 147 gr FMJ specification and test barrel before the final render.

### 3.3 tools/frames.py

Ordinary Python, run outside Blender. It needs astropy, Blender does not.

- Build the bullet's velocity as the muzzle vector (east at 60.9 N) plus the ground point's motion, at the epoch.
- Transform the result into each frame using astropy: ground (ITRS, muzzle only), Earth-centred (GCRS), Sun-centred (HCRS), Galactocentric (astropy defaults, with the parameter set recorded).
- CMB frame: add the solar dipole velocity to the bullet's heliocentric vector. Planck values: 369.82 km/s toward galactic l = 264.02 deg, b = 48.25 deg.
- Write `data/frames.json`: per frame, the speed in km/s, rounded for display, plus the unrounded value, frame name, method, astropy version and parameters.
- Blender only reads `frames.json`. If astropy is unavailable, `frames.json` falls back to the constants in the table below, flagged `"approx": true`, and the HUD prefixes the value with `~`.

Provisional values, all to be replaced by `frames.py` output:

| Frame | Bullet speed | Note |
|---|---|---|
| Ground | 0.305 km/s | muzzle, verify |
| Earth-centred | ~0.53 km/s | + rotation, 0.465 x cos(60.9 deg) = ~0.23 |
| Sun-centred | ~29.8 km/s | Earth's mean orbital speed dominates |
| Galactocentric | ~250 km/s | depends on adopted solar motion |
| CMB | ~370 km/s | dipole +/- Earth's orbital vector, season dependent |

Comparison objects are sourced constants, not computed. Each one is stored with its frame:

| Object | Value | Frame | Status |
|---|---|---|---|
| Saturn V at TLI | ~10.8 km/s | Earth-centred | verify against an Apollo mission report |
| Pioneer 10 | ~12 km/s | Sun-centred, at epoch | verify against JPL Horizons or NASA |

Every source goes in `data/sources.md`. Validation fails the build if a displayed number has no frame or no source entry.

## 4. Visual grammar

### 4.1 Camera locked to the test article

In every layer, the camera follows the bullet or its marker. The bullet stays at the same screen anchor, on the left third line. The world moves. This is the film's single rule of motion, and it is what makes the idea readable without narration: the bullet does not change, the thing around it does.

### 4.2 Frame dust

Each reference frame owns a sparse lattice of points and ticks, the frame dust. It streams past the camera opposite to the bullet's velocity in that frame.

- Streak length = `a + b * log10(v_m_s)`, clamped. The same function in every layer, so streaks visibly lengthen at each frame change.
- One builder generates the dust for every layer. Only density and tint change.
- Dust is mesh or curve geometry, seeded and evaluated from the frame number. No particle simulation.

### 4.3 Frame-change event

The same event every time, lasting about 20 frames:

1. The frame line flips to amber with the new frame name (2 frames).
2. The old dust fades and the new dust fades in with longer streaks (8 frames).
3. The readout rolls from the old value to the new one with eased digits (12 frames).
4. A new tick lands on the ladder.
5. The frame line returns to warm white.

### 4.4 Scale layers and handoff

Blender float precision cannot hold a 3 cm bullet and a galaxy in one scene. So:

- Each layer is its own collection, normalised to about 10 Blender units: L1 range, L2 globe, L3 orbits, L4 galaxy, L5 CMB sphere.
- Inside a layer, the camera pulls out with exponential distance easing.
- Handoff: when the inner layer's hero drops below about 6 px, the next layer's marker for it is already sitting at the same screen position. Crossfade over 6 frames, marker to marker. The inner layer is then hidden.
- Each layer is visible only in its own frame range plus the handoff, which keeps the render cheap.

### 4.5 Palette

Unchanged from v1:

- Background near-black, `#050908`
- Linework phosphor green
- Main text warm white
- Secondary data muted green-grey
- Amber only for frame changes, the overtake lines and the final card

### 4.6 Avoid

Bloom, lens flares, noisy starfields, rainbow gradients, camera shake, every object glowing equally, photoreal attempts, and decorative panels that explain nothing. Never show an unqualified number.

## 5. Builders

Only the bullet is seen close. Everything else is a silhouette or a diagram, which keeps the modelling cheap.

| Builder | Seen as | Notes |
|---|---|---|
| `build_projectile` | macro hero | Lathed profile: ogive nose, shank, flat base. Metallic material, thin wireframe edge pass. The only detailed model. |
| `build_range` | L1 background | Grid plane, distance ticks every 1 m, a muzzle marker. |
| `build_globe` | L2 hero | Low-poly sphere, lat/long lines every 15 deg, terminator from a sun lamp, marker at 60.9 N. No coastlines, since there are no external data. |
| `build_saturn_v` | L2 small pass | Stacked cylinders, interstage bands, cone and escape tower, five bells, one emissive taper for exhaust. Silhouette only. |
| `build_orbits` | L3 hero | Sun disc, Earth orbit circle, Earth marker, inner orbit circles as faint context. |
| `build_pioneer_10` | L3 small pass | Dish, hexagonal bus, three booms. Silhouette. Pioneer 10 has RTGs, not solar panels. |
| `build_galaxy` | L4 hero | Seeded log-spiral point cloud, two main arms and a bar, labelled `SCHEMATIC`. Points via Geometry Nodes instancing or a single mesh, never one object per star. |
| `build_cmb_sphere` | L5 hero | Sphere with a shader: colour = mix(green, amber, 0.5 + 0.5 * dot(N, dipole_dir)), dim. Labelled `CMB DIPOLE (SCHEMATIC)`. |
| `build_dust` | every layer | Frame dust from 4.2. |

Every builder takes a name, a transform, a palette and a seed, and returns a root object.

## 6. HUD

- Layout is hand-authored data in `data/hud_layout.json`: screen-space anchors per segment. No collision solver.
- Elements:
  - shot index, `FRAME 1/5`
  - object block: name and detail
  - big speed readout with units
  - frame line
  - comparison line (`OVERTAKEN BY` / `OVERTAKING`)
  - ladder on the right edge, log scale, one tick per frame
  - final card
- Essential text is at least 28 px tall at 1080p. Everything stays inside title-safe margins.
- Each critical label stays readable for at least 1.2 s.
- Counter roll: do not change text bodies from a frame handler. Handlers are not reliable in background renders and are not saved with the `.blend`. Instead, pre-build one text object per intermediate value (12 per roll) and switch them with keyframed `hide_render`. Deterministic, no handlers.
- The HUD root is parented to the camera. Leader lines are recomputed per frame by the build script and baked as keyframes.

## 8. CLI contract

```bash
python tools/frames.py                                   # writes data/frames.json
blender -b --python scripts/build.py -- --validate
blender -b --python scripts/build.py -- --preview
blender -b --python scripts/build.py -- --preview --start 37 --end 144
blender -b --python scripts/build.py -- --final
```

- `--preview`: 960x540, low samples, writes to `output/preview/`.
- `--final`: 1920x1080, writes a PNG sequence to `output/frames/`. Encode to MP4 with ffmpeg afterwards, so a failed encode never costs a render.
- `--validate`: build and check, print a report, render nothing.
- `--seed N`, `--save-blend PATH`.

Log the Blender version and the effective config at startup. Parse only the arguments after `--`.

## 9. Validation

The build fails if:

- a displayed number lacks a frame, units or a `sources.md` entry
- `frames.json` is missing, or is older than `tools/frames.py`
- any segment overlaps another, or the total exceeds 30 s
- essential text would render below 28 px
- any object outside the current layer is visible during that layer's range, except during a handoff
- any random generator runs without an explicit seed

### Short description (draft)

VELOCITY // FLIGHT TEST 001 follows one 9 mm projectile in slow motion while the instrument changes its reference frame five times: ground, Earth, Sun, galaxy, cosmic microwave background. The bullet never accelerates. Its measured speed rises from 0.305 to about 370 km/s, and along the way it is overtaken by Saturn V and overtakes Pioneer 10. Then the instrument goes back to where it started. Speed is not a property of the object. It is a property of whoever is asking.

### Procedural workflow notes (draft)

The film is built by one deterministic Blender Python script from an empty scene. A separate Python tool computes the bullet's velocity vector in each reference frame for a fixed epoch and location using astropy, and writes the results to `frames.json`. Blender reads that file. Every number on screen comes from it or from a sourced constant listed in `sources.md`. Builders generate all geometry from parameters: the projectile by lathing a profile, the globe, orbits, galaxy point cloud and CMB dipole sphere procedurally, and Saturn V and Pioneer 10 as parametric silhouettes. A data-driven timeline controls the camera, the scale-layer handoffs, the frame-dust streaks (length proportional to log speed), readout rolls and the HUD. No keyframe is set by hand. One command rebuilds the scene, and another renders it.

### Asset and AI disclosure (draft, edit to match what actually happened)

No third-party visual assets, textures, models or fonts beyond Blender's built-in font. All geometry, animation, materials, lighting and typography are generated by script. The specification and parts of the code were written with AI assistance (Claude). No AI-generated imagery or audio.
